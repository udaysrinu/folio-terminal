One-click ordering

Optional setup · about 5 minutes

Without this you type the orders into your broker by hand. With it, one button hands the whole basket to Kite pre-filled, and you review and confirm. Free — Zerodha's Personal plan covers it — pick the Publisher app type.

Setup

1
Open the Kite developer console

Go to developers.kite.trade and sign in with the same Zerodha account you trade from.

2
Create an app

Pick Publisher — free, and its description is literally "HTML/JS buttons for order and basket placement", which is this. Name it anything.

Not Personal or Connect — those are for reading your account over the API, which this never does. Publisher has no API access at all, so it is the least-privileged option.

3
Zerodha Client ID

Your Kite login ID — the one you type to log in, shaped like AB1234. Find it in Kite under Profile, or on any Zerodha statement or contract note.

4
Set the redirect URL

Paste this exactly:

https://udaysrinu.github.io/folio-terminal/

Kite sends you back here after you confirm the basket. It must match what you register, or the handoff is rejected.

5
Copy the API key

The app page shows an api_key — a short string like abcd1234efgh5678. Copy it. Ignore the API secret — this never needs it.

6
Paste it below

It's saved only in this browser and used only to build the handoff form. Nothing is transmitted to me, to GitHub, or anywhere else.

Your API key

← back to the workbench
Your key never leaves this device. This is a plain HTML + JavaScript page with no server and no backend — there is nowhere for it to be sent. It is written to your browser's own storage, read only to build the Kite handoff form, and removed the moment you clear site data or press Remove key. Nobody else — including me — can see it.
If the button later errors about the API key, check that the redirect URL matches exactly.

Is this safe?

An api_key only identifies the app — it can't touch your account. Orders still need your Zerodha login and 2FA on Kite's own site, and you approve every order there. The sensitive half is the API secret, which this never asks for.
